# Metadata-heal: owner/group/mode применялись к файлам только при перевыпуске

**Дата:** 2026-11-09
**Профиль:** bugfix + feature (agent)
**Ветка:** main

## Симптом

При раскатке агентом через Ansible каталог `out_dir` приезжал с правильными
правами (его создаёт и обслуживает сам Ansible), а файлы сертификатов — нет:
оставались `root:root`, целевая группа (например `www-data` для apache2) читать
их не могла.

## Root cause

Права в агенте применяются только внутри `writeFile` — в момент атомарной
записи файла. Но reconcile-цикл устроен как pull с «cheap skip»
(`internal/reconcile/reconcile.go`): пока `(cert_id, valid_until, serial)` в
`.vaultls-state.json` совпадают с vault, агент ничего не скачивает и не пишет.
Типичный сценарий поломки:

1. Первый прогон конфигурации ушёл без `owner`/`group`/`mode` → файлы
   записаны с дефолтами (`0640`, `root:root`).
2. Оператор добавляет `owner: root, group: www-data` в конфиг (Ansible-переменные).
3. Каждый следующий reconcile попадает в cheap-skip — файлы не переписываются,
   права не применяются. До фактического перевыпуска сертификата в vault
   (месяцы для wildcard'ов).

Хуже того: chown в `writeFile` — best-effort (`_ = os.Chown`), т.е. даже при
записи молчаливая неудача никак не проявлялась.

## Решение — metadata heal на каждом reconcile

Файловая цель получила метод `Heal` (`internal/target/file.go`):

- Перечисление артефактов вынесено в общий хелпер `bundleFiles(d, mode)` —
  `writeBundle` и `Heal` ходят по одному списку `(имя, режим)` и разойтись не могут.
  Приватные ключи, как и раньше, всегда `0600`.
- `Heal` статит каждый ожидаемый файл: отсутствующий — пропускает (его напишет
  `Apply`), у присутствующего сверяет perm-биты с конфигом и uid/gid с
  настроенными owner/group (размерность «-1» = не настроена = не дрейф).
- Отличие от `writeFile`: неудачный chown в heal — это ошибка reconcile со
  стадией `heal`, а не молчаливый skip. Оператор явно попросил владельца —
  неработоспособность этого требования нельзя прятать.
- `reconcile.Domain` вызывает heal сразу после чтения стейта, до cheap-skip —
  тем самым покрыты оба пути пропуска записи (cheap-skip и «serial не изменился»).
- K8s-цель `Healer` не реализует намеренно: у Secret нет файловых метаданных
  (необязательный интерфейс `target.Healer`, а не no-op в общем).

Наблюдаемость: счётчик `vaultls_perm_heals_total{domain,cert_id,out_dir}`
(число произведённых ремонтов), стадия `heal` в `vaultls_reconcile_errors_total`
и в статусе домена на дашборде агентов при неудаче.

## Тесты

`TestReconcileHealsPermissionDrift`: деплой → ручной chmod-дрейф всех пяти
файлов → повторный reconcile обязан отремонтировать режимы (`0640`/`0600`)
без скачивания (`dlCount` не растёт — heal работает внутри cheap-skip).
Владельческая ветка chown кроссплатформенно не тестируется (тесты гоняются
не от root), проверяется логикой `lookupOwner`/`ownerDiffers`.

## Эксплуатация

Правка `owner`/`group`/`mode` в конфиге теперь подхватывается на следующем
цикле агента без сброса `.vaultls-state.json` и без перевыпуска сертификата.
