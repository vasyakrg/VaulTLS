# Обновление импортированных сертификатов с историей версий

Дата: 2026-07-29
Статус: согласован

## Задача

Сегодня сертификат можно только создать, импортировать или удалить. Заменить
истёкший или скомпрометированный сертификат новым файлом нельзя — приходится
удалять запись и импортировать заново, из-за чего меняется `id`.

Смена `id` ломает потребителей. `vaultls-agent` тянет сертификат по `cert_id`
из своего конфига и раскладывает в заданный `out_dir`; после переимпорта он
продолжает опрашивать несуществующий id. То же касается привязок
`group_certificates`.

Нужна замена содержимого записи с сохранением `id` и с историей: прошлые
версии остаются доступными для просмотра и скачивания.

## Границы

Редактируются **только импортированные** сертификаты.

| Источник | Признак | Редактирование |
|---|---|---|
| Импорт файла | `is_imported = 1` | да |
| Выпуск внутренним CA | `is_imported = 0`, `ca_id` заполнен | нет |
| ACME | `acme_provider_id` заполнен, `ca_id IS NULL` | нет |

Сертификаты внутреннего CA перевыпускаются штатным путём, а у ACME источник
истины на стороне провайдера — ручная подмена файла разъедет запись с
`acme_client_orders`. Перевыпуск внутренним CA с сохранением `id` в эту работу
не входит.

Область ограничена TLS-сертификатами (`TLSClient`, `TLSServer`). SSH-бандлы
импортировать нельзя в принципе — импорт разбирает только PKCS#12 и PEM, —
поэтому `is_imported = 1` у SSH-записи появиться не может, а `PUT` для такой
записи отвечает 400.

Отозванный сертификат (`revoked_at` заполнен) не редактируется: замена
содержимого записи, уже попавшей в CRL, сделала бы отзыв бессмысленным.
Ответ — 400.

## Модель данных

Миграция `17-certversions`:

```sql
ALTER TABLE user_certificates ADD COLUMN is_imported INTEGER NOT NULL DEFAULT 0;
ALTER TABLE user_certificates ADD COLUMN version     INTEGER NOT NULL DEFAULT 1;
ALTER TABLE user_certificates ADD COLUMN fingerprint TEXT;

CREATE TABLE certificate_versions (
    id          INTEGER PRIMARY KEY,
    cert_id     INTEGER NOT NULL REFERENCES user_certificates(id) ON DELETE CASCADE,
    version     INTEGER NOT NULL,
    data        BLOB NOT NULL,
    password    TEXT NOT NULL DEFAULT '',
    created_on  INTEGER NOT NULL,
    valid_until INTEGER NOT NULL,
    serial_hex  TEXT,
    fingerprint TEXT NOT NULL,
    replaced_at INTEGER NOT NULL,
    replaced_by INTEGER,
    UNIQUE(cert_id, version)
);
CREATE INDEX idx_cert_versions_cert ON certificate_versions(cert_id);

UPDATE user_certificates SET is_imported = 1
 WHERE acme_provider_id IS NULL
   AND ca_id IN (SELECT id FROM ca_certificates WHERE is_imported = 1);
```

Текущая версия живёт в `user_certificates`, вытесненные — в
`certificate_versions`. Версия существует ровно в одном месте, дублирования и
рассинхрона нет. Все существующие чтения сертификата (download, метрики, CRL,
поиск по серийнику, ACME-продление) продолжают работать без правок.

`fingerprint` — SHA-256 от DER leaf-сертификата в hex. Для существующих записей
в SQL не вычисляется, поэтому досчитывается фоновым бэкфиллом при старте — тем
же приёмом, что уже применён для `serial_hex` (`db.rs:959`).

Бэкфилл `is_imported` опирается на `ca_certificates.is_imported`: импорт leaf
автоматически подтягивает чужой CA из цепочки и помечает его импортированным.
Редкий случай — leaf, импортированный под внутренний CA, — останется
нередактируемым; лечится повторным импортом.

### Транзакция замены

Одной транзакцией:

1. текущая строка копируется в `certificate_versions` со своим `version`,
   `replaced_at = now`, `replaced_by = <id вызывающего>`;
2. `user_certificates` получает новые `data`, `password`, `created_on`,
   `valid_until`, `serial_hex`, `fingerprint`, `ca_id` и `version + 1`.

`id` не меняется — агент видит тот же `cert_id` с новым отпечатком и обновляет
файл по расписанию.

## API

```
PUT    /api/certificates/<id>                      заменить текущую версию
GET    /api/certificates/<id>/versions             список версий
GET    /api/certificates/<id>/download?version=N   + существующий download_format=pem
GET    /api/certificates/<id>/password?version=N
DELETE /api/certificates/<id>/versions/<version>   удалить историческую версию
```

Параметр `version` необязателен: без него отдаётся текущая версия, поэтому
существующие клиенты и агент работают без изменений.

### PUT /certificates/&lt;id&gt;

Multipart той же формы, что `POST /certificates/import`: либо `p12` +
`password`, либо `cert` + `key` + опционально `chain`.

| Условие | Ответ |
|---|---|
| `is_imported = 0` | 400 `certificate is not importable` |
| `acme_provider_id` заполнен | 400 `ACME certificates are renewed by the provider` |
| `revoked_at` заполнен | 400 `revoked certificate cannot be updated` |
| тип записи — SSH | 400 |
| CN нового leaf ≠ CN записи | 400, в тексте оба CN |
| тип сертификата не совпадает | 400 |
| цепочка не проверяется | 400 |
| не владелец и не локальный админ | 403 |
| сервисный токен без `cert:issue` либо чужой сертификат | 403 |
| сертификат не найден | 404 |

Цепочка валидируется как при импорте, включая авто-подтягивание CA. Если новый
leaf подписан другим CA (ротация промежуточного), `ca_id` записи переставляется
на актуальный.

Сравнение CN — точное совпадение `name.cn`. Поля записи, не относящиеся к
содержимому сертификата, сохраняются как есть: `name` (включая `ou`),
`user_id`, `renew_method`, привязки к группам. Меняются только поля, вычисленные
из нового файла.

### GET /certificates/&lt;id&gt;/versions

Плоский список, новые сверху:

```json
[{"version":3,"version_id":null,"current":true,"created_on":1753000000000,
  "valid_until":1784000000000,"serial_hex":"0a1b…","fingerprint":"a1b2…",
  "replaced_at":null,"replaced_by":null},
 {"version":2,"version_id":27,"current":false,"created_on":1721000000000,
  "valid_until":1752000000000,"serial_hex":"0c3d…","fingerprint":"c3d4…",
  "replaced_at":1753000000000,"replaced_by":4}]
```

У текущей версии `version_id` равен `null` — она физически хранится в
`user_certificates` и отдельного id не имеет. У исторических — собственный id из
`certificate_versions`.

### DELETE /certificates/&lt;id&gt;/versions/&lt;version&gt;

Только локальный админ. Текущую версию удалить нельзя — 400. Удаление самого
сертификата сносит всю историю по `ON DELETE CASCADE`.

### Права

| Операция | Кто |
|---|---|
| `PUT` (замена) | владелец, локальный админ; сервисный токен со `cert:issue` на сертификатах своего владельца |
| `versions`, `download`, `password` | как сейчас у download: владелец, участник группы сертификата, локальный админ (`can_access_cert_secret`) |
| `DELETE` версии | локальный админ |

История не может быть доступнее текущей версии: те же проверки, тот же код
авторизации.

### Изменение существующих ручек

`GET /certificates/validate?serial=` ищет по `user_certificates.serial_hex`.
После замены серийник вытесненной версии оттуда исчезает, и ранее выданный
клиенту сертификат становится «неизвестным». Поиск расширяется на
`certificate_versions`; найденная по истории запись отдаётся с пометкой, что это
вытесненная версия.

Модель `Certificate` получает три новых сериализуемых поля: `version`,
`fingerprint`, `is_imported`. Первые два нужны агенту для дешёвого детекта
смены — сравнить отпечаток из списка с локальным и качать приватный материал
только при расхождении. Третье нужно фронту, чтобы решать, показывать ли кнопку
обновления.

## Аудит

Два новых действия:

- `UpdateCertificate` — target `certificate`, в detail номер прежней и новой
  версии и новый отпечаток;
- `DeleteCertificateVersion` — target `certificate`, в detail номер версии.

## Интерфейс

В строке действий списка сертификатов (`OverviewTab.vue:110`) добавляются две
кнопки:

- **Обновить** (`pi pi-upload`), видна при
  `canManage(data) && data.is_imported && !data.revoked_at`. Открывает модалку с
  формой импорта: p12 + пароль либо cert + key + chain. После успеха — тост с
  новым номером версии и отпечатком.
- **История** (`pi pi-history`), видна при `canDownload() && data.version > 1`.
  Модалка со списком версий: номер, дата выпуска, срок, укороченный отпечаток с
  копированием, кто и когда заменил, кнопки «скачать p12», «скачать pem»,
  «показать пароль» и «удалить» — последняя только локальному админу и только
  для исторических версий.

Номер версии показывается бейджем рядом с именем сертификата, а не отдельной
колонкой: таблица широкая, а у большинства записей `version = 1`.

## Отвергнутые варианты

**Все версии в `certificate_versions`, `user_certificates` держит указатель
`current_version_id`.** Модель симметричнее, но переписываются все чтения
сертификата: `get_user_cert_by_id`, `get_visible_certs`, метрики,
ACME-продление, бэкфилл серийников. Много риска ради симметрии.

**Версии строками в самой `user_certificates` с парой `(cert_id, version)`.**
Ломает семантику `id` и внешние ключи из `acme_client_orders` и
`group_certificates`.

**Ретеншн «N последних версий».** Отвергнут: p12 занимает единицы килобайт на
версию, а молчаливое удаление истории вредит разбору инцидентов. Версии
удаляются только вручную локальным админом.
